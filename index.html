Framework

The Stack at a Glance

Seven layers connect agent capability to commercial access and accountability.

How to read the stack

  • Foundation (01–02): models and commerce data that agents act on.
  • Mid-stack (03–05): protocols, identity and hosting, and evaluation.
  • Cross-cutting (06): security and compliance across every layer.
  • Top of stack (07): legal, governance, and enterprise access deals.
◆Investment thesis: durable value can concentrate above the commoditizing model layer.
Layer 01 · Model

Models are commoditizing

Back the companies that gain when models get cheaper and interchangeable.

01 · Cheaper

  • Falling inference prices raise margins for agent apps and merchants running millions of shopping tasks.
  • Pure model resellers lose pricing power.

Look for: high-volume agent apps, efficient inference serving

02 · Tuned

  • Open-weight models fine-tuned on catalogs and checkout flows handle narrow shopping tasks at lower cost.
  • Deploy on-premises or on device.

Look for: fine-tuning, distillation, on-device model vendors

03 · Routed

  • No single model wins every task.
  • Routers send hard reasoning to frontier models and simple lookups to small ones.

Look for: model routers, AI gateways, inference orchestration

RememberCheaper · Tuned · Routed
Layer 02 · Data

Agents shop only as well as their data

Whoever holds clean, permitted commerce data decides who wins.

01 · Clean

  • Agents compare products on structured attributes, live inventory, and accurate prices.
  • Clean feeds get picked; messy listings get skipped.

Look for: product data enrichment, feed management, catalog APIs

02 · Consented

  • Sizes, preferences, addresses, and payment choices a shopper grants to any agent.
  • Consent flags the agent must honor.

Look for: consent management, preference vaults, customer identity

03 · Controlled

  • Amazon, Walmart, and Target guard ranking, fulfillment, and seller data.
  • Expect paid, governed agent access through licensed APIs.

Look for: data clean rooms, licensed agent APIs, retail media data

RememberClean · Consented · Controlled
Layer 03 · Protocol

Protocol standards are still in play

Back what works across Universal Commerce Protocol (UCP), Agentic Commerce Protocol (ACP), Agent-to-Agent (A2A), and Model Context Protocol (MCP)—not one winner.

01 · Rails

  • Every agent purchase moves money through cards, stablecoins, or escrow.
  • Rails that add agent authorization, spend limits, and disputes earn per transaction.

Look for: agent payment networks, tokenized cards, programmable escrow

02 · Bridges

  • Merchants cannot rebuild checkout for each protocol.
  • Gateways that translate between UCP, ACP, A2A, and MCP earn from all of them.

Look for: protocol gateways, merchant agent SDKs, commerce middleware

03 · Skills

  • Agents find merchants and services through MCP servers and skills.
  • Curated, verified skill directories decide which tools agents call first.

Look for: MCP server hosting, skill marketplaces, orchestration

RememberRails · Bridges · Skills
Layer 04 · Identity & Hosting

Verify who the agent is and where it runs

Agents cannot transact at scale until a counterparty can verify identity and trust the runtime.

01 · Verify

  • Every transaction needs proof of which agent is acting and for whom.
  • Agent Name Service (ANS) registries, verifiable credentials, and agent OAuth turn that check into recurring revenue.

Look for: ANS registries, credential issuers, agent authorization

02 · Score

  • Completion rates, dispute history, and fraud flags let merchants set terms.
  • A credit score for agents.

Look for: agent reputation, fraud scoring, trust registries

03 · Isolate

  • Enterprises need each shopping agent isolated, metered per agent-hour, and logged for audit.
  • Managed agent runtimes sell those guarantees.

Look for: agent runtimes, sandboxes, confidential compute

RememberVerify · Score · Isolate
Layer 05 · Evaluation

Non-determinism makes measurement a product

Agents give different results on each run, so builders pay for evaluation before scaling.

01 · Test

  • Generic benchmarks miss wrong sizes, stale prices, and bad addresses.
  • Suites built from merchant transaction traces show whether an agent can buy safely.

Look for: commerce eval platforms, golden-dataset providers

02 · Repeat

  • Each model or prompt change can break checkouts that passed last week.
  • Continuous regression turns evaluation into a subscription.

Look for: continuous integration for agents, simulation environments, synthetic shoppers

03 · Certify

  • Merchants need an outside party to confirm task, safety, and cost thresholds.
  • Certification unlocks merchant access.

Look for: AIUC-1-style certification, insurance-linked audits

RememberTest · Repeat · Certify
Layer 06 · Security & Compliance

Guards, proof, and insurance unblock adoption

Prompt injection, agent fraud, and missing audit trails block adoption; tools that remove them get paid.

01 · Guard

  • Product listings, reviews, and emails can carry hidden instructions.
  • Guards that filter inputs and limit tool use protect every purchase.

Look for: agent firewalls, tool-use policy engines, threat modeling

02 · Prove

  • Signed action logs answer Payment Card Industry (PCI), Payment Services Directive 2 (PSD2), General Data Protection Regulation (GDPR), and EU Artificial Intelligence Act questions.
  • Regulators and card networks need to know who approved each purchase.

Look for: agent audit logging, compliance automation

03 · Insure

  • When no human is in the loop, losses need an owner.
  • Risk scoring such as OWASP AI Vulnerability Scoring System (AIVSS) lets insurers price agent errors and fraud.

Look for: agent liability insurance, risk scoring, fraud detection

RememberGuard · Prove · Insure
Layer 07 · Ecosystem

Access and liability set the terms

Technology is ahead of law and commerce; whoever settles access and liability first sets the rules.

01 · Access

  • Amazon blocking Meta’s Muse agent shows platforms can shut agents out.
  • Agent platforms with signed access, data, and revenue-share deals keep an edge.

Look for: agent platforms with merchant agreements, business-to-business agent networks

02 · Liability

  • Shoppers and merchants hold back while it is unclear who pays for a wrong purchase.
  • Contract templates, dispute services, and case law set the rules.

Look for: dispute resolution, agent terms of service, legal tech

03 · Standards

  • Rules at the Linux Foundation (Agent Name Service), OWASP, World Wide Web Consortium (W3C), and International Organization for Standardization (ISO) set interoperability and compliance costs.
  • Those who help write them build for them early.

Look for: standards work, conformance testing, policy advisory

RememberAccess · Liability · Standards
Closing

Key Takeaways

Implications for builders, investors, and policymakers.

01

Value migrates upward

  • Model capability commoditizes. Durable value can concentrate in data, identity, evaluation, and ecosystem positioning.
02

Data is the choke point

  • Portal-specific and consumer data form a moat. Whoever controls access can shape the agent economy.
03

Protocols are the battleground

  • Universal Commerce Protocol (UCP), Agentic Commerce Protocol (ACP), Agent-to-Agent (A2A), and Model Context Protocol (MCP) will influence interoperability and lock-in.
04

Non-determinism demands evaluations

  • Agent commerce needs business-grounded benchmarks and continuous regression testing to scale.
05

Security is cross-cutting

  • Prompt injection, agent fraud, and liability gaps remain adoption barriers across the stack.
06

Ecosystem sets the ceiling

  • Technical readiness is ahead of legal and commercial readiness. Amazon and Muse preview access disputes ahead.
